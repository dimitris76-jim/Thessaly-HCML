# THESSALY-HCML — Flood Forecast Engine v0.5

## Scope
Additive 72-hour hourly rainfall-forcing layer for two pilot basins:
- Pamisos — 146.8 km², using the existing v0.4 representative point.
- Pineios — 6,500 km², using the existing v0.4 representative point.
The existing v0.4 engine and L0–L4 alert logic are not changed.

## Data and outputs
Requests hourly precipitation and 0–7 cm soil moisture from the Open-Meteo forecast API. Returns five windows: 0–6, 6–12, 12–24, 24–48 and 48–72 hours. Each window contains point rainfall, available mean topsoil moisture, low/central/high runoff-volume scenarios and data-point count.

Runoff volumes are scenario estimates using provisional runoff coefficients and initial-loss assumptions. They are NOT calibrated discharge forecasts.

## Integration
Load js/flood-forecast-v05.js after the existing v0.4 engine script:

    <script src="js/flood-forecast-v05.js"></script>

Browser example:

    const result = await window.ThessalyFloodForecastV05.forecast("pamisos");
    console.table(result.windows);

Available basin IDs: pamisos, pineios.

## Limitations
- One forecast coordinate is not a basin-average rainfall estimate, especially for the large Pineios basin.
- The module does not estimate river stage, discharge peak, flood-wave travel time, or inundation extent.
- No operational L0–L4 level is generated by this module.
- The existing v0.4 engine is untouched.
- Experimental decision support only; not an official warning or evacuation trigger.

## Validation gates
1. Replace point rainfall with gridded/sub-basin rainfall aggregation.
2. Validate precipitation against available gauges and radar/satellite products.
3. Calibrate runoff parameters using observed hydrographs and historical events.
4. Add rating-curve-backed stage estimates only where a verified station-specific curve exists.
5. Perform hindcast validation and report error metrics before exposing discharge or stage forecasts.
